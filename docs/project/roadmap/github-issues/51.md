The [living alternatives ADR](https://github.com/iolanta-tech/sparqld/blob/main/docs/project/decisions/implement-live-file-backed-sparql-access-with.md) says to revisit its comparison when new alternatives appear. Vault-LD is not listed.

Vault-LD defines a Markdown-vault format whose frontmatter is interpreted as YAML-LD through shared contexts. It adds Vault-LD-specific processing, including `[[wiki links]]` resolved to IRIs, plus tools to export and ingest RDF:
- [Vault-LD specification](https://vault-ld.org/SPEC/)
- [Vault-LD repository and tools](https://github.com/The-Knowledge-Graph-Guys/vault-ld)

Please update the ADR to evaluate Vault-LD against its existing criteria. The comparison should make the unit clear: Vault-LD provides a vault format and RDF import/export tools, while the ADR compares live queryable graph services. Its documented tools do not appear to provide a live watcher or SPARQL endpoint, so consider whether to compare Vault-LD alone or as part of a stack with a query service.

Also state which semantics the YAML-LD and Markdown-LD columns mean. In particular, distinguish sparqld's Markdown-LD definition (YAML-LD frontmatter) from Vault-LD's extension syntax and processing rules.

Acceptance criteria:
- Add Vault-LD or a clearly justified equivalent solution to the ADR comparison.
- Evaluate it using the same capability criteria and cite current primary sources.
- Record any limits or assumptions, including whether an external SPARQL service is needed.
- Clarify the local meanings of YAML-LD and Markdown-LD in the comparison.
