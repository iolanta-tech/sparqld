The default union counts an identical triple once per source graph. This inflates aggregates and multiplies join results in both HTTP and MCP queries.

Reproduce with two files:

`first.ttl`:
```turtle
<urn:example:subject> <urn:example:value> 10 .
```

`second.ttl`:
```turtle
<urn:example:subject> <urn:example:value> 10 .
```

Serve their directory and run:
```sparql
SELECT (COUNT(*) AS ?count) (SUM(?value) AS ?total)
WHERE { ?subject <urn:example:value> ?value }
```

Expected: count = 1, total = 10. Actual: count = 2, total = 20.

Control:
```sparql
SELECT (COUNT(*) AS ?count)
WHERE { GRAPH ?graph { ?subject <urn:example:value> ?value } }
```
The control should still return count = 2 because the source graphs are distinct.

Verified on 20 October 2026 using the union-default-graph API used by sparqld:
- Locked Oxigraph 0.5.9 / spareval 0.2.6: duplicate count = 2.
- Latest released Oxigraph 0.5.12 / spareval 0.2.8: duplicate count = 2.
- Oxigraph 0.6.0-dev at 7ce152a1d910d5662027a5bcbe7c32cee0a4e059: correct count = 1.

Upstream issue: https://github.com/oxigraph/oxigraph/issues/1919
Merged fix: https://github.com/oxigraph/oxigraph/pull/1920
Latest release checked: https://github.com/oxigraph/oxigraph/releases/tag/0.5.12

The fix is on the development branch and is absent from 0.5.12. An ordinary update within the current 0.5 requirement does not resolve it. The development revision was verified in an isolated engine harness; compatibility with the complete sparqld application has not been tested.

Acceptance:
- Adopt a released dependency containing the fix, or a separately reviewed and validated backport/development pin.
- Return correct COUNT/SUM over shared triples through HTTP and MCP.
- Preserve explicit GRAPH identity and legitimate duplicate solution bindings from distinct matches. SELECT DISTINCT is not a substitute for correcting the union.
- Retain a synthetic regression fixture and record the tested dependency versions.
